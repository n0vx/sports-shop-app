# SPORT STORE

Настольное приложение магазина спорттоваров на Python (Tkinter + MySQL).

## Быстрый старт

1. Установите Python 3.9+ с Tkinter (на Windows и macOS он входит в установщик; на Linux: `sudo apt install python3-tk`).
2. Установите зависимости (драйвер MySQL и Pillow для работы с фото):
   ```bash
   pip install -r requirements.txt
   ```
   Без Pillow приложение запустится, но фото товаров добавить будет нельзя.
3. Запустите сервер MySQL 8+ (или MariaDB 10.4+). Самый простой способ, если установлен Docker:
   ```bash
   docker compose up -d
   ```
   Это поднимет MySQL с базой `sport_store`, пользователем `sport_store` и паролем `sport_store_pass` (поменяйте пароль в `docker-compose.yml`, если база будет доступна кому-то кроме вас).
4. Запустите приложение:
   ```bash
   python app.py
   ```
   При первом запуске откроется форма подключения (сервер, порт, пользователь, пароль, база). Если базы с таким именем нет, а у пользователя есть права, приложение создаст её само, вместе со всеми таблицами и стартовым каталогом из 10 товаров. Настройки запоминаются в `config.ini`, дальше приложение подключается без вопросов.

### Если MySQL уже стоит на компьютере

Создайте базу и отдельного пользователя (один раз, от имени root):

```sql
CREATE DATABASE sport_store CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'sport_store'@'localhost' IDENTIFIED BY 'придумайте_пароль';
GRANT ALL PRIVILEGES ON sport_store.* TO 'sport_store'@'localhost';
```

и введите эти данные в форме подключения. Схема лежит в `schema.sql` (приложение применяет её само, но можно и вручную: `mysql -u USER -p sport_store < schema.sql`).

### Настройки без формы

Вместо формы можно задать переменные окружения `SPORT_STORE_MYSQL_HOST`, `_PORT`, `_USER`, `_PASSWORD`, `_DATABASE` (они важнее `config.ini`). Пример файла настроек: `config.example.ini`. Другой путь к файлу: `SPORT_STORE_CONFIG`.

## Перенос данных из версии на SQLite

Если вы уже пользовались прошлой версией (файл `store.db`), перенесите данные в MySQL:

```bash
python migrate_sqlite_to_mysql.py            # возьмёт store.db рядом со скриптом
python migrate_sqlite_to_mysql.py путь/к/store.db
```

Сначала один раз запустите `app.py` и подключитесь к MySQL. Переносятся пользователи (с паролями и настройками оформления), товары, заказы и их состав. Скрипт работает только с пустой базой: если там уже есть данные, он остановится и ничего не изменит. Всё переносится одной транзакцией, при сбое в MySQL ничего не останется.

## Как пользоваться

- **Первый запуск:** зарегистрируйтесь. Первый созданный аккаунт становится **администратором**.
- **Покупатель:** каталог с категориями, поиском и сортировкой, корзина с количеством, оплата баллами (до 30% заказа), 5% баллами с каждой покупки, история заказов в профиле. Новым покупателям начисляется 500 приветственных баллов.
- **Администратор:** кнопки «Новый товар», «Изменить», «Удалить» на карточках; остатки и цены редактируются прямо из приложения.
- **Фото товаров (только администратор):** на плитке каждой карточки есть кнопка «Добавить фото» / «Сменить фото» — выберите файл, и фото сразу появится в каталоге. Фото можно добавить и в окне товара («Новый товар» / «Изменить»): там есть предпросмотр и кнопка «Убрать фото». Покупатели фото видят, но менять их не могут (права проверяются по базе при каждом действии). Форматы: JPG, PNG, WEBP, BMP, GIF до 20 МБ. Приложение само уменьшает фото до 1000 px, поворачивает снимки с телефона и стирает из файла метаданные (в том числе геолокацию), а в карточке показывает фото с аккуратной обрезкой по краям. Пока фото нет, показывается значок-эмодзи.
- **Оформление (для всех пользователей):** кнопка «Оформление» в шапке и на экране входа. Режим светлая/тёмная, 9 готовых цветов или любой свой через палитру. Изменения применяются сразу, у каждого пользователя сохраняются свои настройки в базе, при входе они подхватываются автоматически.

## Что внутри базы

Пять таблиц InnoDB в utf8mb4: `users` (пароли как PBKDF2-хеши с солью, роль, баллы, оформление), `products`, `product_images` (фото товаров, обычно 20–300 КБ на штуку; хранятся в базе, поэтому видны на всех компьютерах и попадают в резервные копии), `orders`, `order_items`. Если вы уже работали с MySQL-версией без фото, таблица `product_images` создастся при следующем запуске сама. Оформление заказа идёт одной транзакцией с блокировкой строк (`SELECT ... FOR UPDATE`): два покупателя, одновременно берущие последний товар, не смогут продать его дважды, а при ошибке ничего не списывается. При обрыве связи с сервером приложение переподключается само.

## Что изменилось по сравнению с первой версией

- Новый дизайн: карточки товаров, адаптивная сетка, красно-белая палитра по умолчанию, тёмная тема и смена акцентного цвета.
- Настоящая авторизация: пароли хранятся как хеши с солью, права админа выдаются по роли в базе, а не по слову `admin` в логине.
- Данные в MySQL вместо списка в памяти: товары, пользователи, баллы и заказы сохраняются между запусками и доступны с любого компьютера, подключённого к серверу.
- Складские остатки: нельзя купить больше, чем есть.
- Удаление и редактирование по id товара, а не по названию.
- Поиск, категория и сортировка не сбрасываются при смене категории или темы.
- Исправлена категория «Обеспечение/Обувь» → «Обувь».
